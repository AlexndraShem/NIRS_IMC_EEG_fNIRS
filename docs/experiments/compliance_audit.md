- **Дата:** 2026-09-24. Окружение `kaggle` (python 3.11.11, numpy 1.26.4, scipy 1.15.2, sklearn 1.2.2).
- **Повод:** ответ кейсодержателя 2026-09-24 (QA.md 7.2, 8.3, 8.5): явная техническая мета-информация
  (метки/границы текущего блока) запрещена; классификатор «может и должен работать асинхронно»,
  механизм детекции смены инструкции — нежелателен, а если есть — работает всегда и не использует
  длительности инструкций. Решение оценивает человек-эксперт.
- **Что проверялось:** снимок `solution/` на 16:21 (md5 — `scratchpad/compliance/snap_md5.txt`;
  позже другой агент добавил в `solution/eeg_model.py` абляции `use_base/use_nb/use_sm4` и новый
  `solution/artifact_guard.py` — см. §1.3). `solution/` и `results/metrics/` не менялись; всё — в
  копиях `scratchpad/compliance/{sol_snap,sol_p1,sol_p2}`.
- **Протокол чисел:** хронологический (официальная цифра, overlay `data/features/chrono`), 56 сессий.
  Драйвер `src/scripts/compliance_async.py` в режиме «как судья» даёт **побитово те же** ответы, что
  официальный `run.py` (проверено на сессии + 72.4539 = `results/metrics/metrics.json`).

## Скрипты

| скрипт | что делает |
|---|---|
| `src/scripts/compliance_async.py` | драйвер по логике официального `run.py` с меняемым расписанием: `--predict judge\|all` (все точки сетки 250 + 62·j, включая блок 1, состояние 0, паузы), `--chunk K` (push по K отсчётов), `--fit-shift-s`, `--no-fit`; пишет вероятности всех компонент на каждый predict |
| `src/scripts/compliance_compare.py` | совпадение ответов/вероятностей по компонентам с эталоном на окнах судьи, метрики ТЗ, распределение ответов на неоцениваемых окнах |
| `src/scripts/compliance_replay.py` | переигрывание только слияния сдачи (фиксированные вероятности ЭЭГ/NIRS) при перестановке проб внутри блока |
| `src/scripts/compliance_order.py` | то же для разных наборов признаков мета-LR (хронологическое переобучение), + «сброс памяти» между пробами |
| `src/scripts/compliance_meta.py` | хронологическое переобучение мета-LR по вероятностям с любого расписания (в т.ч. всех точек сетки), overlay для прогона |
| `src/scripts/compliance_splice.py` | синтетические сессии: пробы (пауза + 9-с сегмент) переставлены внутри блоков на уровне сырого сигнала ЭЭГ+NIRS (стыки без скачка DC, Frame переносится) |

Структура сессий (все 56): покой 9 с / 0 1.5 с / задача 9 с / 0 1.5 с / … — строгое чередование
покой↔задача, 8 сегментов на блок, в начале блока 0 на 2–6.5 с. Окна судьи — только однородные
окна состояний 1–3 блоков ≥ 2; между сегментами пауза в вызовах ≈ 2.5 с.

вызывается на каждой точке сетки → зависимость исчезает. Без P1 — обновлять `last_clean` на точках
сетки (нужен расчёт вероятностей внутренней модели в `update`).

## 2. Эмпирика: независимость от расписания

Эталон — расписание судьи (`judge`). Сравнение на окнах судьи (86 746 окон, 56 сессий).
«совп. y» — доля совпавших ответов гибрида (в скобках — минимум по сессиям); отклонения — max |Δp|.

| прогон | совп. y | совп. y_eeg | совп. y_nirs | Δ p_ЭЭГ (base/DL) | Δ p_NIRS | Δ слияние | база 60F+30P | итог |
|---|---|---|---|---|---|---|---|---|
| судья (эталон) | 1 | 1 | 1 | 0 / 0 | 0 | 0 | 60.83 | **72.45** |
| predict на **всех** точках сетки, push по 20 отсч. | 0.921 (0.868) | 0.917 | 0.984 | 7e-14 / 0 | 0.86 | 0.83 | 59.44 | 71.06 |
| predict на всех точках, push как у судьи (до события) | 0.921 | 0.917 | 0.984 | 0 / 0 | 0.86 | 0.83 | 59.44 | 71.06 |
| расписание судьи, push по 20 отсч. | 0.994 (0.966) | 1 | 0.985 | 4e-12 / 0 | 0.87 | 0.34 | 60.78 | 72.41 |
| судья, `fit_block` на +3 с (без окон [конец блока, +3 с)) | 0.988 (0.953) | 0.989 | 0.990 | 6e-12 / 0.019 | 0.82 | 0.63 | 60.78 | 72.91* |
| без `fit_block` (7 сессий N01–N02) | — | — | — | p_ЭЭГ нет | нет | — | y ≡ 1 | — |

\* итог другой из-за NIRS-бонуса (другой масштаб NIRS), не сопоставим.

**Локализация.** ЭЭГ (TS-эксперты и DL) от расписания **не зависит** (1e-13 — арифметика).
Расхождения: (а) слияние — состояние шагает только на predict (находка 1): одно это даёт 7.9 %
несовпадений и −1.39 балла в асинхронном режиме; (б) NIRS — от гранулярности push через
восстановление `Frame` (находка 7): 1.5 % несовпадений `y_nirs`, NIRS-метрика не меняется
(0.4414 → 0.4411); (в) сдвиг `fit_block` меняет масштаб NIRS (находка 5) и кэш DL (находка 6) —
это законная зависимость «модель обучена позже».

**Асинхронный режим (текущее решение, predict на всех точках).** Ответы на неоцениваемых окнах:
состояние 0 (подготовка, блоки ≥ 2) — покой 46.0 % / левая 26.0 % / правая 28.0 %; переходные
окна (смесь состояний) — 52.3 / 23.2 / 24.5 %; блок 1 — 100 % «покой» (модели ещё не обучены).
Качество на окнах судьи при этом — 59.44 (база) / 71.06 (итог), т.е. −1.39.

**Патч P1 (такты на сетке)** в `sol_p1`: расписание судьи vs все точки + push по 20 — ответы на окнах
судьи совпадают на **99.3 %** (y_eeg — 100 %), остаток — только NIRS-гранулярность (находка 7).

### 3.2 Какие признаки виноваты (`compliance_order.py`, хронологическое переобучение мета-LR, 51 сессия)

| признаки мета-LR | orig | alt | grouped | reset (быстрые EMA обнуляются в начале пробы) |
|---|---|---|---|---|
| LogLinearFusion (без стекинга, сдача-откат) | 59.52 | 59.60 | 59.57 | 59.63 |
| **F0 — текущие** (τ ЭЭГ ≤ 4, τ NIRS ≤ 4, центр. 60 с) | 60.48 | 60.97 | **59.31 (−1.17)** | **59.36 (−1.12)** |
| F1 — без центрирования | 60.15 | 60.59 | 58.55 | 56.01 |
| **F2 — τ ≤ 1 с + центрирование 60 с** | **60.61** | 61.09 | **60.55 (−0.06)** | 60.20 (−0.41) |
| F3 — τ ≤ 1 с без центрирования | 59.74 | 60.11 | 59.00 | 58.95 |

Вывод: простое сглаживание (LogLinear) к порядку нечувствительно; **весь выигрыш текущего стекинга
(+1.0 к LogLinear) держится на памяти о предыдущей пробе** — при нарушении чередования он исчезает
и даже уходит в минус. Веса мета-LR это подтверждают: у τ = 2 с положительный вес «своего» класса,
у τ = 4 с — отрицательный (детектор «смены» на горизонте 2–4 с, т.е. через паузу 1.5 с в прошлую
пробу). Набор F2 (τ ≤ 1 с) не хуже на исходном порядке и почти нечувствителен к перестановке.
Центрирование 60 с сбалансированность классов не эксплуатирует (grouped даёт 36 с одного класса
подряд — F2 не проседает).

### 3.3 Сигнальный тест: переставленные пробы в сыром сигнале (официальный каркас)

`compliance_splice.py` + драйвер в режиме судьи (= официальный каркас), хронологические артефакты.
Юнит = пауза + 9-с сегмент; перестановка внутри каждого блока (включая блок 1 — within-модели учатся
тоже на переставленном порядке). Стыки портят в основном NIRS (гемодинамика рвётся: NIRS-бонус
11.62 → 9.83/10.19), поэтому сравнивать надо **alt ↔ grouped** (стыки есть в обоих), а не с исходным.
Столбцы: база гибрида 60F+30P / ЭЭГ-стек (y_eeg) 60F+30P.

| вариант | исходный порядок | alt (чередование есть) | grouped (чередования нет) | grouped − alt |
|---|---|---|---|---|
| сдача | 60.83 / 58.38 | 56.54 / 58.73 | 57.57 / 58.87 | **+1.03 / +0.14** |
| A = P3 (τ ≤ 1 с) | 60.99 / 58.37 | 56.90 / 58.64 | 58.47 / 58.84 | +1.57 / +0.20 |
| B = P1 + P2 + P3 (такты, τ ≤ 1 с) | 59.64 / 57.36 | 55.51 / 56.91 | 56.15 / 57.20 | +0.65 / +0.29 |
| C = P1 + P2, текущие τ ≤ 4 с (мета-LR на всех точках) | 60.04 / 57.98 | 55.48 / 57.22 | **51.72 / 54.67** | **−3.76 / −2.55** |

Вывод по сигнальному тесту. Для сдачи и A разрушение чередования **не** снижает качество
(grouped даже проще: меньше смен класса), т.е. на уровне сигнала заметной эксплуатации порядка нет;
вероятностный тест 3.1–3.2 показывает, что у текущего стекинга она есть «в запасе» (при
фиксированных вероятностях −1.1), а P3 её убирает бесплатно. **Вариант C опасен:** если перевести
решение в асинхронный режим (P1), но оставить медленные признаки τ 2–4 с, мета-LR, обученная на всех
точках сетки (с окнами паузы и переходов), начинает прямо опираться на чередование: −3.8 балла при
его отсутствии. P1 допустим только вместе с P3.
