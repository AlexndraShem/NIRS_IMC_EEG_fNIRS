# eeg_lr_features — поднять лево/право в ЭЭГ: правильные каналы, зеркальная аугментация, эксперты

- **Дата:** 2026-09-23. Окружение `kaggle` (python 3.11), CPU (≤ 8 процессов, машина под нагрузкой 20–200).
- **Код:** `src/eeg/lr/` — `base.py` (истинные имена столбцов, лапласианы/биполяры, зеркалирование,
  метрики с F1 по классам и EMA), `analyze.py` (диагностика, ERD-карта), `feats.py` (скрининг
  признаков: within-sLDA + пул-LR LOSubjO, 3 класса и бинарные L/R), `nbcache.py` (кэш узкополосных
  логдисперсий), `evalres.py`/`comb.py` (сравнение и стеки), `final.py` (варианты + пул-артефакты),
  `online.py` (потоковая модель `OnlineEEGLR`), `simulate.py` (поток по всем сессиям + тайминги).
- **Данные:** `data/features/eeg_fb64` (ковариации 7 полос, окна 1/2/4 с), новый
  `data/features/eeg_lr_nb/<сессия>.npz` — дисперсии 23 пространственных каналов (12 биполяр +
  11 лапласианов) в 13 полосах (4-8, 2-Гц 8…30, 8-30), окна 1/2/4 с, строки выровнены с v1_win1.
- **Протокол:** как `src/eeg/common.py`: для блока b — только блоки < b этой сессии + пул других
  участников (leave-one-subject-out). Метрики — среднее по 56 сессиям, блоки 2–7; «EMA1.5» — то же
  после причинного EMA τ=1.5 с (как в `solution/fusion.py`; приближение, только однородные окна).

## Истинные каналы

Столбцы `EEG.Raw`: `[c4, rpa, f8, p8, f4, p4, fp2, o2, cz, pz, fz, o1, fp1, p3, f3, p7, f7, lpa, c3, c7, c8]`.
ERD-карта (`analyze.py`) подтверждает: наибольшая разница L−R в мю/бета — столбец 0 (C4, d′ −0.23)
и 18 (C3, +0.08…0.11); малый лапласиан усиливает до −0.28 / +0.19. Эффект слабый и нестабильный:
знак L−R на лапласиане C3 верен в 68–80 % сессий. Отсюда — потолок L/R на одном окне ≈ 0.65–0.69.

## Выводы

1. **Отдельные «лево/право» признаки (лапласиан C3/C4, биполяры, индекс латерализации) сами по себе
   не лучше полного TS** по точности L/R — полный TS уже содержит эту информацию. Выигрыш от них —
   как от разнообразных экспертов в произведении.
2. **Зеркальная аугментация within** (окна прошлых блоков + копии с переставленными полушариями и
   метками L↔R) — главный новый приём: within-модель на 6 блоках сильно недообучена, симметричный
   априор удваивает данные и регуляризует L/R. На полном TS +2.2 балла у within, на экспертах ещё больше.
3. **Узкие 2-Гц полосы** в 8–30 Гц дают лучшего эксперта, чем 7 широких полос (52.7 vs 51.2).
4. **Длинная интеграция полезна именно для L/R**: окно 4 с у эксперта (или EMA доли L/(L+R) с τ≈3 с)
   поднимает точность L/R до 0.69–0.71, а детекция покоя лучше на коротком окне. EMA τ=1.5 на всём
   векторе при 4-с эксперте почти ничего не добавляет (54.52 → 54.78) — длинное окно уже сглаживает.
5. Больше веса пулу на ранних блоках (0.9 → 0.7 для baseline, 0.8 → 0.5 для экспертов) — +0.8.

## Лучший вариант: `eeg_lr_nbsm4`

`P ∝ P_base · P_nb · P_sm4`, где каждая часть — смесь `P_w^(1-a)·P_p^a` (лог-вероятности с полом
1e-9), `a` линейно по блоку (b=2…7): base 0.9 → 0.7, эксперты 0.8 → 0.5.

- **base** — без изменений `eeg_ts2s_all` (TS 21 канал × 7 полос, окно 2 с, sLDA 0.8, пул
  `pool_ts2s_all_*.npz`), только расписание веса пула и cap 400 обучающих окон.
- **nb** — логдисперсии 23 пространственных каналов (12 биполяр + 11 лапласианов, `base.spatial_matrix`)
  × 13 полос, окно 2 с, нормировка `log(v / медиана v по референсным окнам)`; within-sLDA(0.8) на
  окнах + зеркальных копиях; пул — `data/features/eeg_models/pool_lrnb_{<участник>|all}.npz` (299 призн.).
- **sm4** — TS 11 каналов `[c3,c4,cz,f3,f4,fz,p3,p4,pz,c7,c8]` × 7 полос, ковариация за 4 с,
  свой RefState по прошлым блокам; within-sLDA(0.8) + зеркало; пул `pool_lrsm4_*.npz` (462 призн.).

**Вероятности:** `data/probs/eeg_lr_nbsm4.pkl` — получены **потоковой** симуляцией `OnlineEEGLR` по
всем 56 сессиям (чанки 100 мс, LOSubjO-пулы), т.е. ровно то, что выдаст онлайн; формат как у
`eeg_ts2s_all.pkl` ({сессия: (n_окон, 3)}, NaN на блоке 1, строки = `v1_win1`). Также
`eeg_lr_sched.pkl`, `eeg_lr_nb.pkl`, `eeg_lr_ens4.pkl` (оффлайн-сборка из скрининга).
Сверка потока с оффлайн-сборкой: без cap |ΔP| ≤ 6e-6, argmax 100 %; с cap отличие до 4e-2 из-за
float32-признаков оффлайн-кэша (argmax 99.7 %), поэтому эталоном сохранён поток.

**Время** (1 поток BLAS, `EIG_THREADS=1`, 8 параллельных симуляций на загруженной машине):
predict среднее 8.2 мс, p99 9.8 мс, макс 19 мс; push чанка 100 мс ≈ 3.7 мс; fit_block по блокам
1…7 среднее 0.46/0.61/0.76/0.71/0.72/0.80/0.77 с, максимум 0.99 с. Основная часть — base
(ref 0.25 с + TS 0.55 с + sLDA 1617 призн. 0.3 с до cap); эксперты добавляют ≈ 0.3 с.

## Перенос в онлайн (`solution/eeg_model.py`)

1. Скопировать `OnlineEEGLR` из `src/eeg/lr/online.py` (или добавить к `EEGTangentPool` два эксперта):
   - второй буфер/окно: хранить 4 с полосовых сигналов 7 полос (21 канал) — ковариация 4 с по
     каналам `SM` для sm4, последние 2 с — для base;
   - поток nb: после префильтра `x @ W.T` (W 23×21 из `spatial_matrix("bip")` + `("lap")` по
     **истинным** индексам столбцов) → 13 полосовых sosfilt с zi → буфер 2 с → дисперсии;
   - в каждой точке сетки 250 мс сохранять (cov2, cov4_sm, var_nb);
   - `fit`: те же размеченные окна; ts_ = max(2, ceil(n/400)), rs = 2·ts_; base — как сейчас;
     эксперты — RefState/медиана по `[::rs]`, признаки `[::ts_]`, sLDA на `vstack(X, X[:, fi]*fs)` с
     метками `swap_lr(y)` для копии (индексы `feature_mirror` зависят только от монтажа — можно
     посчитать при инициализации или положить в артефакт);
   - `predict`: блок = число выполненных fit_block + 1; веса пула по расписанию; сумма трёх
     нормированных лог-вероятностей → softmax.
2. Артефакты: `pool_ts2s_all_all.npz` (как сейчас), `pool_lrnb_all.npz`, `pool_lrsm4_all.npz`
   (формат `PoolLR`: mean/scale/coef/intercept) из `data/features/eeg_models/`.
3. Имена каналов в `solution/eeg_model.py` (`EEG_LABELS`, `CHSETS`) — заменить на истинный порядок
   (сейчас используется `chans="all"`, поэтому base от этого не зависит, но эксперты — зависят).
4. Опционально на стороне слияния: иерархическое сглаживание (P(покой) без/с малым τ, доля
   L/(L+R) с τ≈3 с) вместо EMA τ=1.5 по всему вектору — +1.1 на ЭЭГ-only (55.88 vs 54.78).
