# online_harness — онлайн-каркас сдачи `solution/`: контракт, допущения, инструменты

- **Дата:** 2026-09-22 (обновлено после переноса боевых моделей). Окружение `kaggle`
  (python 3.11.11, numpy 1.26.4, scipy 1.15.2, scikit-learn 1.2.2). Данные — 56 сессий
  `data/raw/Data/*.mat`.
- Этот файл — про **каркас** (контракт судьи, форматы, инструменты) и про исторический
  baseline stage0. Финальные модели, метрики и времена — **`docs/experiments/final_pipeline.md`**.
- **Результаты:** `results/metrics/` (боевая конфигурация, честный LOSubjO-вариант),
  `results/metrics_all_pool/` (пул `_all`), `results/online_runs/<сессия>/{predictions,timings}.csv`;
  baseline stage0 — `results/{metrics,online_runs}_baseline_stage0/`.
- Запуск: `python solution/run_all.py --input data/raw/Data --jobs 6` (см. `DEPLOY.md`).

## Состав `solution/`

| файл | назначение |
|---|---|
| `classifier.py` | `OnlineClassifier(meta)`: `load`, `push`, `predict`, `fit_block` — тонкий, терпимый к формату слой |
| `base.py` | интерфейс модальностной модели `ModalityModel`: `update(stream)` / `fit(ends, y)` / `predict_proba(end)` |
| `eeg_model.py` | `EEGTangentPool` (боевая): фильтр-банк 7 полос → ковариация 2 с → рецентрированное TS → within-sLDA(0.8) × пул-LR; `EEGLogVarLDA` — baseline stage0 |
| `nirs_model.py` | `NirsCascadeEns` (боевая): 4 банка → 58 производных каналов → каскад 8 × 4 sLDA; `NirsLagLDA` — baseline stage0 |
| `fusion.py` | `LogLinearFusion` (боевое): w·log P_eeg + (1−w)·log P_nirs + лог-приор → причинное EMA по реальному времени; `MeanProbaFusion` — baseline; интерфейс `decide(probas, end, fs) → {y, y_eeg, y_nirs}` |
| `stream_utils.py` | сетка окон, разметка окон по меткам отсчётов, разбор meta / чанков / меток |
| `session_io.py` | чтение .mat (v5 и v7.3) — только для `run.py`/`score.py`, классификатор его не импортирует |
| `run.py`, `score.py`, `run_all.py` | реконструкция каркаса судьи, метрики §5, прогон каталога |
| `artifacts/config.json` | выбор моделей (`"module:Class"`) и гиперпараметры |
| `artifacts/eeg_pool.npz` | кросс-субъектная пул-LR ЭЭГ (64 КБ), обучена оффлайн |
| `tools/parity_check.py`, `tools/contract_selftest.py`, `tools/degrade_test.py` | dev: паритет с оффлайн-вероятностями, самопроверка контракта, тесты деградации |

**Как подключить новую модель:** класс-наследник `ModalityModel` в `solution/<файл>.py`,
в `config.json` → `"eeg_model": "<файл>:<Класс>"` (или `nirs_model`). Модель получает в
`update` новые отсчёты (ЭЭГ: `(n, C)` + концы окон сетки, на которых надо запомнить признаки;
NIRS: `(m, 36)` + Frame), в `fit` — концы всех размеченных окон завершённых блоков и метки,
в `predict_proba(end)` возвращает вероятности классов 1..3 или `None`. Кросс-сессионные веса —
через `load(artifacts_dir)`.

## Реконструкция каркаса (`run.py`)

- Данные подаются хронологически: ЭЭГ-чанки по 250 мс (границы — глобальная сетка
  `round(k·62.5)` ∪ границы блоков), NIRS — отсчёты с `Frame ≤ текущего конца` в виде
  `{"HbO", "HbR", "Frame"}`.
- `predict` — после чанка, конец которого совпадает с концом окна 1 с, целиком лежащего в
  однородном сегменте States∈{1,2,3} блоков 2..7 (сетка = `src/dataset/windows.py::window_ends`).
- `fit_block(k, States[блок k])` — сразу после последнего отсчёта блока k (k = 1..7);
  последнее окно блока предсказывается **до** `fit_block` этого блока.
- `meta = {session, eeg_fs, eeg_channels, eeg_labels, has_nirs, nirs_fs, nirs_channels}`.
- Хронометраж: `time.perf_counter` вокруг каждого вызова `push` / `predict` / `fit_block`.
- `score.py`: G (строки — ответы, столбцы — истина), F1_k, min-F1, macro-recall для `y`,
  `y_eeg`, `y_nirs`; истинные метки перепроверяются по .mat, контроль полноты сетки окон;
  агрегат — среднее по сессиям (NIRS — по 54 сессиям, где он есть); штрафы §5.4 по максимуму.

## Допущения о контракте судьи (классификатор терпим ко всем вариантам)

| что | основной вариант | ещё поддержано |
|---|---|---|
| `meta` | dict с `eeg_fs`, `eeg_channels`, `nirs_fs`, `has_nirs` | любые регистры/синонимы, вложенные `{"EEG": {"Frq"}}`; пустой dict → 250 Гц, каналы по первому чанку, fs NIRS — по числу отсчётов на ≥ 30 с Frame (притяжение к типовым 3.90625/12.5/… в пределах 5 %) |
| `eeg_chunk` | `(n, 21)` | `(21, n)`, dict `{'Raw'|'data': …}`, один отсчёт `(21,)` |
| `nirs_chunk` | dict `{HbO, HbR, Frame}` | `None`/пусто; `(HbO, HbR[, Frame])`; массив `(m, 36)`; `(m, 37)` со столбцом Frame; без Frame отсчёт считается пришедшим в момент push |
| `predict()` | окно = последняя 1 с полученного ЭЭГ | конец окна не обязан лежать на сетке |
| `fit_block(k, labels)` | States ЭЭГ-отсчётов блока k; блок = `[конец блока k−1, +len)` | кумулятивные States с начала сессии; по метке на каждый `predict` с прошлого `fit_block`; пары `(end_sample, y)`; dict/DataFrame |

`tools/contract_selftest.py` прогоняет сессию в вариантах (случайные размеры чанков,
транспонированный ЭЭГ + пустой meta + кумулятивные метки + NIRS-массив с Frame; NIRS без Frame +
пооконные метки; вложенный meta + кортеж NIRS) — ответы совпадают с каноническим на 100 %
(перепроверено с боевыми моделями на 5 сессиях: обе без NIRS — `2025.12.18.12.09.22_N03`,
`2025.12.18.15.02.14_N02`; обе с NIRS 3.9 Гц — `2025.12.09.12.52.43_N01`, `2026.02.19.13.23.35_N13`;
и обычная `2026.01.20.13.28.05_N08`).

`tools/degrade_test.py` — сценарии деградации (ни разу не вызван `fit_block`; в блоке нет части
классов; NIRS обрывается в середине сессии; NIRS не приходит вовсе; NIRS начинается с блока 3;
пустые чанки): падений нет, форматы ответа корректны, при обрыве NIRS `y_nirs` пустеет через
≤ 10 с (`nirs.max_stale_s`) и гибрид переходит в ЭЭГ-only. Подробности — `final_pipeline.md`.

Замечено: NIRS приходит пачками — у ≈ 65–70 % соседних отсчётов одинаковый Frame (пакет раз в
≈ 0.4 с), т. е. реальная задержка NIRS до 0.4 с; медиана шага Frame для оценки fs бесполезна.

Правила: вся обработка причинная (sosfilt + сохранённое zi, x − x[0] по первому отсчёту),
признаки только по прошлому (`[end − 2 с, end)` у боевой ЭЭГ-модели, `[end − 1 с, end)` у
baseline; NIRS — отсчёты с Frame ≤ end); разметка окон по-прежнему по однородности 1 с;
States — только для разметки
окон в `fit_block`; блок 1 не классифицируется; расписание протокола не используется
(сетка 250 мс — это шаг решений из ТЗ, не расписание).

## Паритет с оффлайн-оценкой stage0 (историческое, baseline; текущий паритет — `final_pipeline.md`)

| модель | оффлайн minF1 / recall | онлайн minF1 / recall | совпадение ответов по окнам |
|---|---|---|---|
| ЭЭГ logvar sLDA | 0.4244 / 0.5552 | 0.4258 / 0.5557 | 99.71 % (min 89.0 %) |
| NIRS sLDA (54 сессии) | 0.3879 / 0.5333 | 0.3879 / 0.5333 | 100 % |
| гибрид (среднее вероятностей) | 0.4466 / 0.5928 | **0.4479 / 0.5933** | 99.85 % (min 94.3 %) |

С z-нормированными вероятностями `data/probs_stage0.pkl` (`w_lv_z`, `w_nirs_z`) совпадение
99.70 / 100 / 99.83 % — z-нормировка для LDA действительно почти ничего не меняет.

**Единственный источник расхождений — точность кэша, а не каркас.** `src/dataset/io.py` хранит
`EEG.Raw` в float32; при амплитудах до 6.8·10⁹ (DC) шаг квантования ≈ 512 ед., что сравнимо
с амплитудой ЭЭГ малых каналов. Онлайн-каркас читает .mat в float64. Проверка на худшей
сессии `2026.01.20.13.28.05_N08`: онлайн-признаки на float64 отличаются от кэша до 47 по
log-дисперсии (3 % признаков > 1e-3), а при подаче того же сигнала, приведённого к float32, —
max |Δ| = 3.9e-6. Затронуты 4 сессии (N08 01.20: 89 %, N14 03.27: 96 %, N01 12.04: 98 %,
N10 02.09: 99.9 %). Онлайн-вариант (float64) корректнее; на средние метрики влияние +0.001.
**Совет для исследовательского кода:** кэшировать ЭЭГ в float64 или после вычитания x[0].

## Времена baseline stage0 (все 56 сессий, 6 процессов на общей машине, load average 40–55 на 32 ядра)

| вызов | n | p50 | p95 | p99 | max | лимит |
|---|---|---|---|---|---|---|
| predict | 86 050 | 0.53 мс | 1.3 мс | 12 мс | 147 мс | 200 мс |
| fit_block | 392 | 88 мс | 225 мс | 377 мс | 476 мс | 1.5 с |
| push (не штрафуется) | 134 053 | 1.2 мс | 5.5 мс | 17 мс | 75 мс | — |

Хвосты predict (> 10 мс) — вытеснение процесса планировщиком на перегруженной машине, а не
вычисления (типичный predict < 1 мс). fit_block растёт с числом окон (блок 1 ≈ 30 мс,
блок 7 ≈ 110 мс медиана). Исправлено по ходу: `import pandas` внутри разбора меток стоил
≈ 1 с на первом `fit_block` — убран; в `load()` добавлен прогрев sklearn LDA (теперь также
батч-`eigh` и двухклассовая sLDA — их использует боевой код).

Времена боевой конфигурации (predict p50 4.4 мс / max 12.7 мс, fit_block p50 682 мс / max 1.00 с)
и выбор прореживания — в `final_pipeline.md`.

## Открытые вопросы

- Официальные `run.py`/`score.py`/`DATASET.md` не выданы: точные форматы `meta`, `nirs_chunk`,
  `labels`, порядок `predict`/`fit_block` на границе блока и способ учёта штрафов (по max или
  по среднему) — предположения; при получении оригиналов прогнать `contract_selftest.py`.
- Сессии без NIRS: `y_nirs` пуст → в NIRS-агрегат не входят (у нас 54 из 56). Как судья
  усредняет NIRS при наличии таких сессий в закрытом наборе — неизвестно.
- Лимит predict в ТЗ дан дважды: 0.25 с (§3.3) и 0.20 с (§5.4); ориентируемся на 0.20 с.
