# subject_pool — прошлые сессии того же участника: подучастниковые пулы ЭЭГ и NIRS

- **Дата:** 2026-09-23. Окружение `kaggle` (python 3.11.11, numpy 1.26.4, scipy 1.15.2,
  scikit-learn 1.2.2). Все 56 сессий, оценка — окна блоков 2–7, среднее по сессиям.
- **Повод:** ответ кейсодержателя 2026-09-23 — закрытый тест = по одной **новой сессии тех же
  участников**, в `meta["subject"]` передаётся участник ("N06"), для теста можно использовать все
  train-данные, включая сессии того же участника.
- **Код:** `src/eeg/exp_subjpool.py` (скрининг пулов-LR ЭЭГ), `src/nirs/exp_subjpool.py` (скрининг
  NIRS-пулов), `src/eeg/exp_subjpool_eval.py` (смеси + слияние как в `solution/fusion.py`),
  `src/eeg/build_subjpool.py`, `src/nirs/build_subjpool.py` (артефакты).
  Онлайн: `solution/eeg_model.py::EEGTangentPool` (`subject_pool_dir`, `subject_weight`),
  `solution/nirs_model.py::NirsCascadeEns` (`subject_pool_dir`, `pool_weight_rt/lr`),
  `solution/base.py::subject_of`, `solution/classifier.py` (`fusion_params_subject`).
- **Артефакты сдачи** (`solution/artifacts/`, всего 1.3 МБ): `eeg_pool.npz` — общий пул на всех
  56 сессиях (без изменений), `eeg_subj/<участник>.npz` — LR (C = 0.1) на всех сессиях участника,
  `nirs_subj/<участник>.npz` — 12 бинарных sLDA каскада на всех сессиях участника с NIRS.
- **Dev-артефакты leave-one-session-out:** `data/features/subjpool_loseso/<сессия>/`
  (`eeg_pool.npz` — общий пул без этой сессии, `eeg_subj/`, `nirs_subj/` — пулы участника без
  этой сессии), 9.2 МБ. Подмена — `solution/run.py --loseso-artifacts` / `run_all.py
  --loseso-artifacts` / `src.scripts.judge_eval --loseso-dir`.
- **Результаты онлайн** (официальный каркас): `results/subjpool/<прогон>/metrics.json` + `runs/`
  (`loseso_final` — сдача в прокси теста, `losubjo_final` — сдача при незнакомом участнике).

## Идея

Касательное пространство каждой сессии уже рецентрировано по её собственному референсу (ЭЭГ —
блок 1 / прошлые блоки, пул — вся сессия), NIRS — нормирован std блока 1. Поэтому модели,
обученные на других сессиях того же участника, можно применять к новой сессии без адаптации.
Подучастниковый пул — отдельная модель, которая подмешивается к within и общему пулу:

- **ЭЭГ:** `log P = 0.2·log P_within + 0.5·log P_общий + 0.3·log P_участник` (было
  `0.2·within + 0.8·общий`). Пул участника — LR (C = 0.1, `class_weight="balanced"`,
  стандартизация) на TS-признаках его сессий. Нет пула участника → вес 0.3 уходит общему пулу
  (ровно прежняя модель); нет within (блок 1 без 3 классов) → пулы нормируются на 1.
- **NIRS:** для каждого из 12 членов каскада — sLDA на всех окнах сессий участника (L/R — окна
  задачи ≥ 3 с), логиты смешиваются с within: `z = 0.5·z_within + 0.5·z_pool` отдельно для
  «покой/задача» и «лево/право». До обучения within (или если within не обучился) — только пул.
- **Слияние:** если пул участника ЭЭГ загружен — `eeg_weight 0.7`, приор `[0, 2.5, 2.5]`
  (`fusion_params_subject`); иначе прежние `0.75`, `[0, 2, 2]`. NIRS с пулом участника стал
  сильнее, поэтому ему выгоден больший вес.
- `fit_block` не меняется (пулы предобучены, не дообучаются); `predict` + 1 матричное умножение
  1617×3 и 12 скалярных произведений.

## Протоколы

- **A — leave-one-session-out** (прокси теста): для сессии S пулы обучены на всех остальных
  сессиях (общий — 55 сессий, участника — его остальные 2–4 сессии).
- **B — хронологический:** пулы только из сессий с более ранней датой (дата — префикс имени).
  «GB» — все более ранние сессии всех участников (строго по правилу организаторов);
  «G0B» — другие участники целиком + более ранние сессии своего (смешанный, как раньше LOSubjO).
  У 14 сессий нет более ранних сессий участника → откат на общий пул.

## Риски

- Веса смеси (0.2/0.5/0.3, NIRS 0.5/0.5) и слияния (0.7, 2.5) подобраны на тех же 56 сессиях
  (сетка ~60 точек); выигрыш устойчив по обоим протоколам, но A-оценка чуть оптимистична.
- Если судья не передаст `subject` (и имени сессии с `_N<id>`) — автоматический откат на прежнюю
  модель (общий пул на 56 сессиях + прежнее слияние), это ≈ `loseso_base`.
- Пул участника обучен на 3–5 его train-сессиях; если тестовая сессия сильно отличается
  (другой монтаж/день), вес 0.3 ограничивает вред: без within/общего пула он один хуже базы.
